0 The established frame ESTABLISHED

Recorded for orientation — nothing here needs review.

Four primitives: Task (unit of intent; status, accumulates context, decomposes) · Session (one execution attempt, one agent, one place; runtime state + resume handle) · Document (own lifecycle; kinds: spec, design, report, knowledge-entry, review-record) · External reference (Linear / PR / CI / branch — optional anchor, never core schema).

Protocol is bookended by the session lifecycle: context.pull at start, context.push at checkpoints/end. Not a chatty live broker.

Workflow — hot, solodispatch · re-orient · resume
Review — warm, collaborativespec review · sanity checks · fork decisions · promotions
Knowledge — cool, durablesearch · reference · subscribe

One substance on a temperature gradient — knowledge is cooled workflow re-entering as future input.

1 Convergence principles PROPOSED

Emerged from walking the flows, not designed in. Ratify, amend, or reject each.

C1 One digest, three consumers

The context.pull core payload, the handoff.render artifact, and the re-orientation screen are the same digest — consumed by next-you, a teammate, and the next agent. One renderer; R3 (human + LLM readable) satisfied by construction.

C2 Pushes, not sessions, are the source of truth

Resume-after-death and re-orientation are the same mechanism: a new session seeded by context.pull over the predecessor's pushes. A live resume handle is just an optimization. Losing a session loses keystrokes, never context.

C3 Adoption rides on session-start hooks

Dispatch can begin inside the agent: a hook performs context.pull + session.register automatically. Product adoption does not depend on human discipline, and the product never taxes the moment of dispatch.

C4 Review is a decision-hardening pass

review.conclude writes the outcome back to the task as a decision; future pulls serve it as binding context. Review is not a separate world — it is how a decision gets a second pair of eyes before it binds.

C5 Knowledge carries provenance

Every promoted knowledge entry links to the session(s) and task that established it — the D13 differentiator (AI-native management) made concrete.

3 Delegate-and-detach, walked PROPOSED

Tuesday 9:40am: "fix the flaky CI" (no ticket) and "implement session-resume" (DDAK-142, approved spec).

  1. Frame. Task exists, or dispatch is session-first and a provisional task is created (F-A).
  2. Choose executor. CC-local / CC-web / Cursor-web. Adoption is the contract; launch is sugar (F-B).
  3. Context assembly. context.pull fires — see section 4.
  4. Detach. You hold a dispatch receipt: task link, session entry, the agent's declared checkpoint cadence.
  5. Re-attach triggers. (a) agent pushes a question → "waiting on you" in workflow (hot/solo — not review); (b) you re-orient by choice; (c) external-ref event (CI fail, PR review) attaches to the task.
  6. Resume. session.resume_handle — URL for web sessions, directory + session id for CC-local. Dead handle ⇒ new session on the same task, seeded by pull over prior pushes (C2).

Staleness-aware, not liveness-aware

No polling (bookended principle forbids it). A session is marked silent past its declared cadence; the digest reports "last heard 40m ago, last state: running tests" — what it knows and when, never pretending to know more.

Pressure test: bake-off

One task, N parallel sessions racing. Digest shows per-session state side by side. Your pick of the winner is recorded as a decision on the task; losers marked abandoned with reason — exactly the management judgment that today evaporates.

Pressure test: scope drift

Agent on task A incidentally fixes task B's thing. Agent declares "also touched X" in a push; AI matches it to an existing task (weak ref, already modeled) or proposes a new one.

5 Review surface PROPOSED

A review record holds

The ask (one line: "approve this spec" / "sanity-check this approach" / "pick fork A or B" / "promote this to knowledge?") · the subject (document / digest / fork statement / knowledge candidate — version-pinned, F-E) · AI-assembled context ("what you need to know", drill-down links into workflow) · reviewers + state · response controls matching review.act.

proposed → open → (comment / request-changes cycles) → concluded(outcome) → archived-but-linked

Conclusion writes the outcome back to the task as a decision (C4).

Review kinds

spec / design review · mid-stream sanity check (default non-blocking) · fork decision — your R1 rule turned into a team-scale mechanism, not a discipline · knowledge promotion (the gate's review path).

AI assistance

Assembles the context packet · drafts a review brief (what changed, what's really being asked, where to look) · pre-reviews (F-F) · condenses the concluded thread into the outcome record.

6 Promotion gate PROPOSED

Worked example: CI-flake task closes; a push contains "two test processes race on one DuckDB file; fix is per-test temp dirs." Durable knowledge — under explicit-only it dies in the task; under always, everything is noise.

  1. Trigger. AI proposes at boundaries — task close, explicit condense, review conclusion (F-G). Explicit promote always available.
  2. Condense. AI drafts the candidate entry from the push stream; you edit.
  3. Review. Blocking by default for knowledge. AI pre-review checks the candidate against existing entries: "contradicts K-12 — supersede?" (reuses the supersedes relation).
  4. Approval. Becomes a knowledge entry with provenance links to its source sessions and task (C5).
